# Julia and the Pro Simulator

**Decision, 2026-10-17 (Ali): "JAX first, Julia later if needed".** New features are built in
TOMAS-JAX on the sparse Rosenbrock solver in `prototypes/julia/jax_sparse_spike/` (full-MCM size:
about 1.6 s per simulated day at 15 min coupling and 4.4 s at 1 min, at matched accuracy). TOMAS.jl
(private) keeps the Julia plan and prototype as a tracked option.


Status: 2026-10-17, branch `feat/pro-julia`. Nothing here changes the AAAR tutorial. TOMAS-JAX
stays the tutorial engine: frozen, bit-identical, fixes only.

Why (Ali, verbatim): "you should also deploy agents for Julia development since I think that has
much faster runtime if it is desiged properly to have it on laptops. That way we can tackle full
MCM. Do you agree? You should make a plan for it. I think attention is the key for development by
chunking the problem into small pieces to increase accuracy." Later: "I mean mcm too. And it will
be all the new features and updates."

**Where the work goes.** The whole box model is being ported to Julia in the private repository
[reflective-org/TOMAS.jl](https://github.com/reflective-org/TOMAS.jl). This covers TOMAS
microphysics, MCM gas chemistry, photolysis, SOA partitioning, N2O5 uptake, the coupling
driver and the scenario and result contract. Every new feature goes there after the port
reaches parity. TOMAS-JAX at a pinned stable tag is the reference the port is validated
against.

**The plan** is TOMAS.jl `docs/TOMAS_JL_PLAN.md`: benchmark results, architecture, validation,
work packages with gates, timeline, risks, decisions and review notes.

**What the benchmark found** (gas chemistry only, 5742 species, 24 h, matched accuracy, same
machine and sessions):

- a sparse solver, in either language, is 500 to 1200 times faster than today's dense tutorial
  solver;
- between Julia and sparse JAX, neither is clearly faster: from JAX 1.7 times faster to Julia
  2.4 times faster, depending on the method, the error measure and the coupling interval.

## In this repository

| Path | What it is |
|---|---|
| `docs/pro/julia/BENCHMARK.md` | the shared benchmark: problems, files, references, metric, timing protocol, and the dense-JAX and scipy baselines |
| `prototypes/julia/bench/` | the benchmark's generators and scoring: `export_problems.py` (problem files from TOMAS-JAX), `verify_export.py`, `reference.py`, `check_references.py`, `compare.py`, the JAX dense and scipy runners and batches; `problems/MANIFEST.json`, `reference/CHECKS.json`, the batch logs and every run's `_timing.json` |
| `prototypes/julia/jax_sparse_spike/` | the sparse JAX spike (Ros3, Rodas3, Rodas4 and Ros2 with a levelised sparse LU), its logs and timing summaries, including the review's runs (`results/rv*`) |

The problem, reference and full result files (about 200 MB) are not committed. They are
regenerated by `prototypes/julia/bench/scripts` (BENCHMARK.md section 10), whose `MANIFEST.json`
and `CHECKS.json` pin their sizes, hashes and accuracy. The Julia spike that was timed is in
TOMAS.jl, `prototypes/julia-spike/`. Earlier commits on this branch held a copy of it under
`prototypes/julia_bench/julia/`.
